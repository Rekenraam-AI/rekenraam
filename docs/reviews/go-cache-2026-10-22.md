# Go workload cache alignment (#382)

Date: 2026-10-22. Parent source: `645d909d2528f8e9c3c1292a1f3fe3059aec751e`.
The implementation and tests are in the same commit as this record.

## Configuration and scope

Push/PR CI disables setup-go's automatic cache and explicitly restores/saves
`go env GOCACHE` and `go env GOMODCACHE`. Those paths are exported to all later
steps. E2E global setup passes the environment to its real `pnpm build` child
without overriding GOCACHE. The new child-process control covers both unset
Go defaults and an inherited explicit path containing spaces.

The workload writers are race, coverage, build, e2e-app and e2e-audits. Keys
include native configuration, go.sum, workload and source inputs, with fallback
to earlier source in that workload, other compatible workloads, then older
dependencies within the same native configuration. A source-only change can
save a refreshed immutable key. Exact hits do not create new entries; neither
run IDs nor timestamps enter the key. The existing per-ref cancellation and
branch scopes remain; matrix jobs have distinct writers. GitHub's repository
quota and inactivity eviction bound retained storage, which must still be
observed during hosted validation to detect eviction churn.

Native fingerprint inputs include the selected Go version and target,
CGO/compiler flags, FTS5/netgo/osusergo, compiler/libc versions and runner image.
No runtime dependency, bundled SQLite, FULL setting, race assertion, test
package deadline/concurrency, event selection or independent build scheduling
changes. All five logical gates remain (six jobs including the browser matrix).

The optional `GO_PHASE_TIMINGS=1` adds a module prefetch and compile/link/vet
pass without running tests (`-exec /bin/true -count=1`), followed by the original
complete test command. Synthetic successes do not enter the test-result cache.
The execution phase includes cached Go-driver/link overhead, and valid test
result cache hits are still permitted, as before. The build also separates
embedded-output compilation/testing and the production trimpath build.

No package deadline or concurrency setting was changed to obtain these passes.

## Timing interpretation and hosted acceptance

The first local empty-build-cache attempt recorded vet 105.00s, race compilation
139.15s and trimpath build 94.87s. Workloads ran concurrently and frontend
assets changed between builds, so these are diagnostic observations, not a
controlled speedup or a fresh-runner comparison. The pre-existing module cache
also means this was not a cold module-download run.

E2E's subsequent build confirmed the inherited paths in its child log and
recorded embed compile/vet 0.65s, real embed test 0.49s and trimpath build 3.04s.
Module prefetch took 0.04s. Frontend build and browser execution are additional
costs. These figures do not establish recoverable savings for the full setup.
The complete E2E global setup measured 81.982s including the frontend build;
its warm Go phases total about 4.22s. Browser execution still dominates this
local run. The separate backend runs record the following warm phases, with
no remote transfer cost:

| Workload | Module prefetch | Vet | Compile/link/default vet | Execution command |
| --- | ---: | ---: | ---: | ---: |
| Race | 0.01s | 0.78s | 6.70s | 259.51s |
| Non-race coverage | 0.01s | 0.51s | 5.67s | 217.37s |
